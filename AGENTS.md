# AGENTS.md

Guidance for coding agents working in this repository. It covers only what the code can't tell you: design rules and the reasons for them, Wikipedia quirks, and how changes land. Read the code for layout, dependencies, and commands.

## Design rules

- Keep the module layering `config` and `errors` → `cache` → `parsing` → `validation` → `transform` → `plotting` → `output` → `cli`. Each module imports only package modules to its left, and I/O happens only in `cache`, `output`, and `cli`. Nothing runs at import time. Register new modules in `LAYERS` in `tests/test_architecture.py`, which also forbids imports of I/O and network modules from pure modules and disallows `# type: ignore` and `# noqa` in `spacex_graphs/`.
- Parsing and transform functions take everything they need as arguments, including the date: `cli.run` computes today's UTC date once and passes it down. Launch times on Wikipedia are UTC, so "today" is too.
- Identical data must produce byte-identical SVGs, which is why they are saved with no timestamp and a fixed `svg.hashsalt`. The scheduled workflow commits only files that changed, so any nondeterminism becomes a noisy daily commit.
- The change-detection hash includes today's date on purpose: the cumulative chart's current-year line extends to today, so the graphs legitimately change once a day. It also includes `cli.code_version()`, a fingerprint of the package source and rendering libraries, so a code change or dependency update regenerates the outputs without waiting a day.
- The program writes only to the output and cache directories, `outputs/` and `.cache/` by default. `cli.run` passes them to every function that does I/O, so tests pass temporary directories rather than patching module globals.
- Keep SVG filenames and orbit category labels stable. The README embeds the SVGs by filename and the scheduled workflow commits `outputs/*.svg` and `outputs/*.csv`. Chart titles may change.
- Leave committing generated SVGs and CSV to the scheduled workflow. It runs tests and renders in Docker with a digest-pinned base image. Use the same checkout, UTC date, data, and Docker platform (`linux/amd64`) to reproduce its SVGs byte for byte. Matplotlib uses bundled DejaVu Sans, but FreeType builds and other platform rendering differences can change native renders.
- `config.ORBIT_CATEGORIES` is the one list of orbit categories. A new `ORBIT_MAPPING` value must be in it and get a color in `plotting.py`. The tests check both, and the bar chart refuses a category it can't color. Check contrast in both themes when changing palette colors. `plotting.DARK_MODE_DATA_COLORS` holds substitutions for colors that need more contrast against the dark background. `output.py` embeds the SVG dark-mode styling, which `tests/test_output.py` verifies.
- Records keep Wikipedia's outcome text and reported mass, or `None` when there isn't one. `validation.outcome_kind` classifies the outcome, and `transform.launch_succeeded` uses that classification to decide whether mass counts in the graphs. Keep both policies out of the parsers.
- Data that can't be trusted raises a subclass of `errors.DataError`, which the CLI turns into exit code 1 and a one-line message. Put new completeness checks in `validation.py` as pure functions raising such errors, rather than logging a warning, so the daily job goes red instead of publishing.
- The frames passed between `transform`, `plotting`, and `output` use the column names in `transform.Col`; refer to those rather than repeating the strings.
- The committed `outputs/spacex_launches.csv` is the baseline for `validation.check_published_launches`. Every published launch must still be found by exact date and vehicle, ignoring time, and no published mass may become unknown. There is no tolerance for either loss because small losses add up across runs. A known mass also fails the check if it drops by more than `MAX_PUBLISHED_MASS_DROP_FRACTION` (50%) and by at least `MIN_PUBLISHED_MASS_DROP_KG` (1,000 kg). If a genuine Wikipedia change triggers one of these guards, delete the CSV in the same PR that explains why, so the next run publishes a fresh baseline.
- `validation.check_recent_launch` fails when the newest launch is more than `MAX_DAYS_SINCE_LAUNCH` (30) days old, which is how new launches that stop parsing get noticed. If SpaceX really pauses that long, raise the limit until launches resume.
- In the cumulative chart, the current year is red and years before `HIGHLIGHT_FROM_YEAR` (2020) are grey on purpose: their payload mass is tiny next to recent years. The palette covers at most eight years including the current year. Starting in 2028, earlier years outside that rolling window also fold into the grey group.
- Chart titles say "launched", not "to orbit", because the totals include suborbital (Transatmospheric) payloads.
- Each chart carries a clock-free caption from `transform.chart_caption` with the source and license, the latest launch in the data, and the number of successful launches that count as 0 kg because their mass is unknown. Separately, `transform.cumulative_summary` includes `today` in the cumulative SVG's `<desc>` when the current year is present, matching the line that already extends to that date. The current year's bar is labelled "YTD".

## Wikipedia quirks

- Falcon and Starship tables use different column layouts, so `parsing.py` has a row parser for each, picked by the layout each `config.Page` declares. Planned launches sit in tables with fewer columns and must stay excluded.
- A page that parses to zero launches is a fatal error with exit code 1. That almost always means Wikipedia changed a table layout; keep it fatal, or the daily job would publish graphs with that page's launches missing.
- A payload's mass is the figure attached to a unit: "kg" first, then tonnes ("t" or "tonnes"), then pounds ("lb" or "lbs"), converted to kg. Numbers without a unit are never masses, so footnotes, years, satellite counts, and the "500-2" in "CAS500-2" are ignored, and a cell with no unit has no mass. "Unknown", "Classified", and "—" mean no mass (`None`), not 0.
- Each year Wikipedia moves the previous year's launches out of the current Falcon list into a page of their own. When that happens, add a `Page` for it to `WIKIPEDIA_PAGES`, with the table layout its rows use. Until then, the run fails with `MissingYearsError`, because every past year since `FIRST_CONTINUOUS_YEAR` must have launches.
- When Wikipedia can't be reached, cached pages are used only if they were confirmed current within `STALE_CACHE_LIMIT`; past that the run fails. Keep it failing rather than raising the limit to get a green run: frozen data that looks current is worse than a red job.
- Keep the descriptive User-Agent and request timeout, which Wikimedia's User-Agent policy asks for, and keep fetch concurrency at its current level.

## Dependencies

- Edit `requirements.in` (runtime) or `requirements-dev.in` (tools), then run `scripts/update-locks.sh` to regenerate both locks; it needs uv, which `requirements-dev.txt` installs. The `requirements*.txt` locks carry hashes that pip enforces, so hand edits break installs, and CI fails when a lock doesn't match its `.in` file.
- Dependabot waits 7 days after a release before proposing it, so a compromised or broken release is usually yanked first. Keep the same cooldown when upgrading by hand: `UV_EXCLUDE_NEWER=<UTC timestamp a week ago> scripts/update-locks.sh --upgrade`. Use the environment variable, not `--exclude-newer`, which uv writes into the lock header that CI's sync check and Dependabot compare against.
- Python 3.15 is the target. Change its version everywhere at once: `requires-python`, ruff's `target-version`, and mypy's `python_version` in `pyproject.toml`; `--python-version` in `scripts/update-locks.sh`; `python-version` in `tests.yml`; the Dockerfile's base image, which also sets the version for `auto_update.yml`; and the README.
- Run `scripts/check.sh` with the locked development dependencies installed to mirror the Python, audit, and lockfile checks in CI. It regenerates and compares locks in a temporary directory without changing the working tree. It also runs `actionlint`, `hadolint`, and `shellcheck` when installed locally.
- The locks are resolved for the exact `--python-version` in `scripts/update-locks.sh`, and uv silently skips any release that needs a newer Python. Keep that version equal to `requires-python`, the oldest Python the project supports. A Dependabot PR that won't move a package past a security alert is often this: soupsieve's fixes were held back because they need 3.11.5 and the locks targeted 3.11.0.

## Commits and pull requests

- Use Conventional Commits, such as `fix(parsing): …` or `ci: …`. The scheduled workflow's own commits are `chore(outputs): update graphs by scheduler`.
- To bring a PR branch up to date with `main`, rebase onto `main` and force-push with `--force-with-lease`. Don't merge `main` into the branch, including through `gh pr update-branch`'s default merge mode, so history stays linear.
- When a change alters the graphs, attach before-and-after renders to the PR, and update the README if behavior or outputs change.
